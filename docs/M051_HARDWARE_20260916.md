never updated; it is not evidence that Intel was deleted. New runs initialize
this verification field to null and display `NOT_CHECKED` until verified.

## Repair 1.1.1

`REPAIR_AUDIO.cmd` locates the reviewed run's journal, verifies its version,
mode, known INF hash/certificate, ownership and successful-snapshot record,
then rechecks the live device. It accepts Problem 0 or 28 only with empty
Service and INF, on the same exact hardware and instance. It never repeats
installation, null binding or MMIO access. A changed binding causes refusal.

Deletion uses [PnPUtil](https://learn.microsoft.com/en-us/windows-hardware/drivers/devtest/pnputil-command-syntax)
with `/delete-driver` for the verified unused probe only, without `/uninstall`,
`/force` or `/reboot`. The live package identity is resolved again immediately
before deletion. Intel package bytes and service policy are checked afterward;
only the original run's owned certificate can be removed. Existing snapshot
files and the before/after journals are included in the repair report.

The old fresh-install guard still requires Code 28. The revised coordinator
does not repeat the probe on an unbound target with retained Intel. Source
tests exercise the observed Problem 0 result, foreign/changed bindings,
ownership races, package-in-use errors, report/journal failures, certificate
errors, changed Intel state and idempotent repeated repair.

The September 17 report RESULT_REPAIR_Repair_20260917_201735_9ce9d36c.zip
confirms deletion of oem37.inf (PnPUtil exit 0), retained Intel package/service
checks, and the unchanged snapshot. Final binding is UNBOUND with Problem 0,
empty Service and INF. Physical cleanup is verified; audio remains absent.
DSP boot/authentication, firmware transport, IPC, codecs, DMA and WaveRT remain
unimplemented. This correction contains no new hardware-writing operation.
